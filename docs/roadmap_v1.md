## 1. 試合バランスの合わせ直し（①）
軽量化のあと、試合エンジンの基準を合わせ直す（架空の固有12で確認）。

- 目標（前に決めたとおり）
  - 各リーグに3割打者が5人前後、30本塁打が7人前後。
  - 首位打者は.310以上、本塁打王は30本以上。
  - 球界の4番級は ミート・パワー90前後、エース級は165km・オール90前後まで育つ環境。
- 合わせる値：打球の強さの基準、球威の基準値（1軍の平均）、当てやすさ、ボール球への手出し。
- 確かめ方：5シーズン回し、毎年の指標が大きくずれていかないこと（インフレしないこと）を見る。
- あわせて見る指標：四球率（いま約6% → 8%前後へ）、盗塁王の数（13章）、セーブ・ホールドの数。

## 2. 経営の調整（②③）
- **初期の資金**
  - 全球団 **150億円**。
  - 自球団だけは、リーグを始めるときに **50億〜200億円（10億円単位）** から選べる（開始画面に設定を追加）。
- **球場は1つに固定**
  - 収容人数は **12球団とも 50,000人**。
  - 観客数の差は、人気・成績・チケット価格だけで付く。
- 収入（入場料・放映権・スポンサー）と運営費の水準を合わせ直す。
  - 収容人数が増えるので、入場料収入の水準も見直す。
  - 目安：平均的な球団の収支がほぼ均衡。強い・人気のある球団は黒字、低迷が続くと赤字。

## 3. 画面（⑥⑦⑧）

### 3-1. 順位表（⑥）
- オープン戦と交流戦は、**12球団を1つにまとめた順位表** で表示する（リーグ別にしない）。
- 公式戦は今までどおりリーグ別。

### 3-2. 日程画面（⑦）
- 文字と余白を小さくし、カレンダーと試合カードの大きさの釣り合いを整える。

### 3-3. 選手の一覧を出すすべての画面（⑦）
- 打順を決める画面（スタメンの行）の幅・形を、選手を一覧で出すすべての画面に当てはめる。
- 対象：ベンチ入り・投手・全選手・2軍・補強の各画面（FA・トレード・自由契約・戦力外）・コーチ・ドラフト候補。
- 1行の形を共通の部品にして、どの画面でも同じ見た目・同じタップ動作にする。

### 3-4. スマホの見た目の全体設計（⑧）
- **基本の形**
  - 1行1人の一覧
  - 上に絞り込み（セグメント）
  - 下に主な操作ボタン（固定）
- **文字の大きさは3段階に統一**：見出し・本文・補足。
- **色の使い方**：濃紺は試合・重要、黄色は選択中、赤は警告、灰色は補足。
- **余白**：画面の端8px、カードの中10〜12px、行と行の間は詰める。
- **タブの多い画面**：横スクロールのタブで、選んだタブを中央に寄せる。
- **確認の進め方**：Galaxy S25 の画面幅（約384px）で全画面を確認し、はみ出し・折り返しをなくす。

### 3-5. オーダー画面の操作（追加修正）
- 選手を **タップしても入れ替えの選択状態にしない**。タップは「選んだ選手の能力」を表示するだけにする。
  - 何人もタップして、能力を見比べられるようにするため。
- 入れ替え・移動は **ドラッグだけ** で行う。

## 4. 育成（⑨⑩⑱⑲）—— 大きく変更

### 4-1. 成長の基本：経験値（EXP）で能力が上がる
- 能力ごとに経験値をためて、一定量たまると +1 上がる。

| いまの能力 | +1 に必要な経験値 |
|---|---|
| 〜60（C） | 1,000 |
| 61〜80（B・A） | 1,500 |
| 81〜90 | 2,000 |
| 91〜 | 2,000 |

- **試合で手に入る経験値**：**出場した選手だけ**、全能力に入る（ベンチで出なかった選手は0）。
  - 野手：1試合ごとに **+15**。
  - 投手：1登板ごとに **+18**、さらに投げた1イニングごとに **+5**（アウトの数で数える）。
    - 年間フルに投げた先発（25登板・150回）と中継ぎ（55登板・55回）が、どちらも同じくらい育つ比率。投げていないイニングの分は入らない。
  - 2軍戦は1軍戦の ×0.5、3軍戦は ×0.3。
- **衰え**：過渡期・衰退期は今の仕組み（年齢で毎年下がる）のまま。経験値で上がる分と差し引きにする。

### 4-1b. 3軍戦
- 3軍戦を新しく作る。**スコアや結果は残さない**（経験値を配るためだけの試合）。
- コーチ欄に **3軍監督** を新設する。3軍監督が自動でオーダーを組み、選ばれて出場した選手に3軍戦の経験値（+6）が入る。
- 対象は、1軍・2軍の試合に出ない選手（育成選手など）。
- **練習で手に入る経験値**：練習メニューで選んだ **特定の能力に +8**（毎日。オフの10・12月は自主トレで ×0.5）。
- 実際に入る経験値 = 上の値 × **選手固有の成長率** × **成長フェーズの倍率**（育成期 ×1.2、成長期 ×1.5、全盛期 ×0.5、過渡期 ×0.4、衰退期 ×0.2）。
- 調整の目標：**リーグトップの選手が OVR 85〜90 あたりで頭打ちになり、ずっと上がり続けない**こと。
  - 経験値の基本の量（+15・+18・+5・+8）は、この目標に合わせて決めた値（企画時の +20・+10 から調整。隠れた倍率は使わない）。
  - 確認（10〜12シーズン）：投手のトップは88前後、野手のトップは90前後で止まる（才能の高い1〜2人は92〜93まで）。リーグ平均のOVR・打撃成績は年を追っても変わらない。

### 4-2. 練習メニューを能力と1対1にする（⑩）
- **いまの問題**：選手詳細の練習指示（9種類）と、成長の計算が受け付ける指示（4種類）が食い違っていて、「おまかせ」以外は効いていない。
- **直し方**：練習メニューを能力と1対1にする（選んだ能力に練習の経験値 +10）。
  - 野手：ミート・パワー・選球眼・チャンス・走力・肩力・送球・捕球・守備（メインの位置）
  - 投手：球速・球威・制球・スタミナ・ピンチ
  - **投手の変化球練習**：**球種ごとに、キレ・重さ・変化量のどれを伸ばすか** を選べる（例：スライダーのキレ、フォークの変化量）。
  - 共通：体力・回復力
  - 「おまかせ」：経験値を全体に分ける。

### 4-3. 春季・秋季キャンプ（⑨）
- **春季キャンプ（1月1日〜31日）**
  - 連れていく選手を **最大50人** 選び、選手ごとに練習メニューを指示する。
  - 効果：普段の練習の **×2**。
  - 連れていかない選手は2軍キャンプ（普段の練習の **×1.3**）。
- **秋季キャンプ（11月）**
  - 連れていく選手を **最大30人** 選び、個別に練習メニューを指示する（効果 ×2）。
  - 参加しない選手は休養（体力・怪我の回復が早い）。
- **費用**：キャンプに連れていく **1人につき500万円**（球団の資金から払う）。
- **CPU球団**：自動で選ぶ。

### 4-4. 選手固有の成長率：才能と向上心（潜在能力の考え方をやめる）
- **潜在能力（成長の上限）という考え方はやめる**。上限はなく、成長率の差で伸び方が決まる。
- 各選手に **才能（1〜100）** と **向上心（1〜100）** を持たせる。
  - 才能の倍率：1 で ×0.5、50 で ×1.0、100 で ×1.5（式：0.5 + 才能 ÷ 100）。
  - 向上心の倍率：同じく 1 で ×0.5、50 で ×1.0、100 で ×1.5。
  - **成長率 = 才能の倍率 × 向上心の倍率**（×0.25〜×2.25）。
- 入団後に「50%の確率で才能どおりに伸びる」のような運の要素は入れない。成長率どおりに伸びる。
- **成長フェーズ（成長曲線）**
  - 早熟・普通・晩成ごとに、年齢でフェーズ（成長期・全盛期・過渡期・衰退期）が進む。
  - **過渡期・衰退期に入った選手は、毎年10%の確率で1つ前のフェーズに戻る**。
  - そのため、同じ早熟でも成長のピークが選手によってずれる。
  - 戻ったときは、お知らせで伝える（例：「◯◯が復調の兆し」）。
- **これまでの「潜在能力の更新（⑱）」は、この成長曲線の更新に置き換える。**

### 4-5. ドラフトとスカウト
- ドラフト候補の能力は、**±5 の幅** で表示する（例：ミート 55〜65）。
- **スカウトメモ** に、架空のアマチュア成績を載せる。
  - 高校：地方大会、甲子園大会
  - 大学野球、社会人野球、独立リーグ
- **才能・向上心はスカウトが見抜く**。見抜ける精度はスカウト眼力しだい。
  - 眼力 D50 で ±20、S100 で ±5（その間は比例。50未満はさらに幅が広い）。
  - 例：眼力50のスカウトが「才能70」と見た選手は、本当は50〜90のどこか。

### 4-6. 才能・向上心の編集（⑲）
- 初期選手編集の画面で、潜在能力の代わりに **才能・向上心** を編集できるようにする。

## 5. 記録（⑤⑫⑮⑯）

### 5-1. 月間MVP（⑤）
- 毎月、両リーグで投手1人・野手1人を選ぶ（3・4月は合算、9・10月も合算。NPBと同じ）。
- 決め方：その月の成績の点数をもとに、記者投票を再現する（ベストナインと同じ考え方）。
- 表彰画面と選手の記録に残す。

### 5-2. 歴代記録と殿堂入り（⑫）
- **シーズン記録・通算記録のランキング**（歴代トップ10）
  - 打撃：安打・二塁打・三塁打・本塁打・塁打数・盗塁・得点・四球・死球・打率・出塁率・長打率・OPS
  - 守備：失策・補殺・刺殺
  - 回数：各タイトルの受賞回数・猛打賞の回数・マルチヒットの回数
  - 投手：勝利・セーブ・ホールド・奪三振・防御率など（今までどおり）
  - 死球は試合エンジンにまだないので、死球（投球が打者に当たる）を新しく入れる。
- **連続記録**：連続試合出場・連続試合安打・連続試合出塁・連続無失点（投手）・連続セーブ成功
- **試合ごとの記録**
  - 打者：猛打賞、サイクルヒット、1試合4本塁打、満塁本塁打、サヨナラ打
  - 投手：完封、無四球試合、ノーヒットノーラン、完全試合、1試合の奪三振
- **節目の記録**：2000本安打、200勝、250セーブなど（名球会の基準）。達成するとお知らせを出す。
- **殿堂入り**
  - 引退した選手を、通算成績・タイトル・表彰から点数にする。
  - 記者投票を再現し、得票率75%以上で殿堂入りにする。

### 5-3. 球団の歴史と自分の戦績（⑮）
- **球団の歴史**：年度ごとの順位・勝敗・日本一、主な選手（タイトル・ベストナイン）、監督の変遷。
- **自分の戦績**：就任した球団の履歴、通算の勝敗、優勝・日本一の回数、最もよかったシーズン。

### 5-4. 過去の試合のアニメ再生と守備成績（⑯）
- **アニメ再生**
  - そのシーズンの自球団の試合を、保存してある1球ごとのデータからアニメで再生する。
  - 対象は自球団の試合。他球団の試合は、設定で記録している場合だけ。
- **守備成績**：選手ごと・守備位置ごとに、守備イニング・刺殺・補殺・失策・併殺を記録する。選手詳細と記録画面で見られるようにする。

## 6. 采配と駆け引き（⑬）
- **盗塁と盗塁阻止**
  - 走者の走力、捕手の肩、投手のクイックで成否が決まるようにする。
  - 盗塁阻止率を記録する。
  - 目標：盗塁王30個前後、リーグの盗塁成功率70%前後。
- **守備シフト**（一部、先行して作業中）
  - 打者の打球方向の傾向（パワーのある打者ほど引っ張る）に応じて、引っ張りシフト・流し警戒を敷ける。
  - 相手のシフトは打席の前に表示し、流し打ち・引っ張りで逆を突ける。CPU監督も判断力に応じて敷く・逆を突く。
  - あとで：セーフティバント、打者ごとの打球方向の記録。
- **配球の駆け引き**（実装済み）：初対戦は内角で意識させ、2打席目以降は外の変化球。打者一巡までは変化球を隠す。
- **采配の多様化**
  - エンドラン、スクイズ、敬遠、左右の継投（ワンポイント）、代走・守備固めの使い分け。
  - CPU監督は傾向（バント多用・機動力など）と判断力で使い分ける。

## 7. 移籍と監督人事（⑭⑰）

### 7-1. トレードの評価に将来性を入れる（⑰）
- CPU球団がトレードを受けるかどうかの計算に、若い選手の将来性（才能・向上心と年齢・成長フェーズ）を入れる。
- 将来性をどれだけ正しく見抜けるかは、CPU監督の手腕しだい。
  - 手腕が低い監督：将来性を見誤る（高く見すぎる・低く見すぎる）。
  - そのため、「伸びる若手」で主力を獲れることも、逆に断られることもある。

### 7-2. 解任されたとき（⑭）
- **他球団からの打診**（実装済み）に、**1年浪人** を加える。
- **浪人**
  - 1シーズンは試合に関わらず、日付だけ進む（結果は見られる）。
  - オフに、監督を交代した球団から打診が来る。成績の悪い球団ほど打診しやすい。

## 8. 軽量化（⑪）
- **使っていない旧エンジンを削除する**：`matchup_engine`・`fielding_engine`・`game_state`・`test_*`・`physics_logic`・`physics_model` と、使っていない確認用ツール。
- **アプリの容量**：Android は端末の種類ごとに分けて作る（いま73MB → 20〜25MB の見込み）。
- **初期データ**：固有12の初期データ（約8万行）を小さく持つ（文字列を詰める、または圧縮）。
- **保存データ**：1球ごとの記録は、シーズンを越えたら要約だけ残す（アニメ再生はそのシーズンのみのため）。
- **動作の速さ**：「シーズンを最後まで進める」と、日々の進行の重い処理を見直す（スマホで目に見えて速くする）。

## 9. 実装の順番（案）

| 段階 | 内容 | 理由 |
|---|---|---|
| A | ⑪軽量化 → ①バランス → ②③経営 | 土台。旧エンジンを消してから合わせ直すと確認が速い |
| B | ⑥順位表 → ⑦日程・選手一覧の共通化 → ⑧スマホ全体 | 以降の画面を作る前に、共通の部品と見た目を固める |
| C | 経験値の仕組み・才能と向上心 → ⑩練習メニュー（変化球練習を含む） → ⑨キャンプ → 成長曲線の更新 → ドラフトの見え方・スカウトメモ → ⑲才能・向上心の編集 | 育成のつながり。⑩は不具合の修正も兼ねる |
| D | ⑤月間MVP → ⑯守備成績・アニメ再生 → ⑫歴代記録・殿堂 → ⑮球団の歴史・自分の戦績 | 記録は、守備成績など元のデータを先にそろえる |
| E | ⑬盗塁・シフト・采配 → ⑰トレードの将来性 → ⑭浪人 | 試合の駆け引きは①のバランスの上に作る |

各段階の終わりに、テストと数シーズンの確認を回し、S25 で動作を確かめる。
